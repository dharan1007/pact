Integrate PACT
DEVELOPER PRODUCT

Use PACT as a runtime, not a demo.

The release ships an importable ESM SDK, validated adapter and real-provider contracts, HTTP/REST integrations, WebMCP and MCP agent bridges, durable authority primitives and a machine-readable product manifest. The Helios flow remains only a reference scenario.

real-provider.mjs
import { createPactExternalRuntime } from '/sdk/runtime.js';
import { createPactRestIntegration } from '/sdk/http.js';

const integration = createPactRestIntegration({
  id: 'acme.projects', version: '1.0.0',
  baseUrl: 'https://api.example.com',
  headers: { authorization: `Bearer ${process.env.PROVIDER_TOKEN}` },
  resourcePath: ({ intent }) => `/projects/${intent.projectId}`,
  plan: async ({ intent, state }) => ({
    effects: [{ path: 'project.owner', before: state.project.owner, after: intent.newOwner }],
    invariants: [{ path: 'project.plan', equals: state.project.plan }]
  }),
  buildApply: ({ plan }) => ({ method: 'PATCH', body: { owner: plan.effects[0].after } }),
  verify: async ({ state, plan }) => state.project.owner === plan.effects[0].after
});

const pact = createPactExternalRuntime({
  integration,
  verifyApproval: request => verifySignedApproval(request)
});
REAL SYSTEMS

Execute the approved plan against the actual provider.

createPactExternalRuntime() reads the remote canonical state before preview, binds the plan to the provider revision, re-reads that revision immediately before commit and rejects stale state before any write. createPactRestIntegration() sends the revision as If-Match and propagates the PACT idempotency key to the provider.

If the provider applies a change but the response is lost, PACT marks the commit uncertain instead of blindly retrying. Verification re-reads the real provider and can recover a receipt without applying the effect twice. Provider credentials belong on the server-side only; never expose them to browser or WebMCP code.

adapter-runtime.mjs
import { definePactAdapter } from '/sdk/adapter.js';
import { createPactRuntime } from '/sdk/runtime.js';

const adapter = definePactAdapter({
  id: 'acme.flags', version: '1.0.0',
  describe: () => ({ name: 'Feature flags' }),
  plan: async ({ intent, state }) => ({
    effects: [{ path: `flags.${intent.flag}`, before: state.flags[intent.flag], after: true }],
    invariants: [{ path: 'billing.plan', equals: state.billing.plan }]
  }),
  verify: async ({ intent, state }) => state.flags[intent.flag] === true
});

const pact = createPactRuntime({ adapter, initialState,
  verifyApproval: async request => verifySignedApproval(request)
});
GENERIC RUNTIME

Your adapter supplies the plan. Your application supplies authority.

plan() receives the intent and cloned canonical state, then returns declarative effects and invariants. PACT rejects mismatched preconditions before approval, binds the exact plan to SHA-256, checks canonical version before commit, rechecks invariants, calls verify() and emits a receipt.

verifyApproval must validate the approval artifact and return at least humanPrincipal and agentSession. Those claims are hashed into authority and the final receipt.

server-authority.mjs
import { createPactAuthority } from '/sdk/authority.js';
import { createRedisAuthorityStore } from '/sdk/redis-store.js';

const authority = createPactAuthority({
  store: createRedisAuthorityStore({
    url: process.env.PACT_REDIS_REST_URL,
    token: process.env.PACT_REDIS_REST_TOKEN
  }),
  verifyApproval: request => verifySignedApproval(request)
});
SERVER AUTHORITY

Make commit authority opaque, bound and single-use.

Capabilities are bound to transaction ID, exact plan hash, canonical base version and verified identity claims. Commit authorization atomically consumes authority; only a retry with the same idempotency key can replay the same authorization.

Production integrations require a durable atomic store. The static reference deployment does not provide that guarantee yet.

HTTP connector
import { createPactHttpConnector } from '/sdk/http.js';

const api = createPactHttpConnector({ baseUrl: 'https://example.com' });
const request = new AbortController();
await api.preview({ intent }, { signal: request.signal });
await api.commit({ txId }, txId, { signal: request.signal });

// Caller cancellation => PACT_HTTP_ABORTED
// Connector deadline => PACT_HTTP_TIMEOUT
request.abort();
REMOTE PACT SERVICE

One HTTPS contract for apps, CLIs and agent hosts.

The connector posts to /api/pact, enforces HTTPS outside localhost and requires an idempotency key for commit and rollback before network I/O. Every operation accepts an AbortSignal, keeping caller cancellation distinct from connector timeout.

Discover the HTTP envelope, integration runtime and bridges from /pact-manifest.json.

WEBMCP

Page-scoped transactional tools through document.modelContext.

The bridge targets the current experimental WebMCP producer surface, observes execution cancellation and exposes only the annotation fields supported by the current draft. Remote API/provider output is marked untrustedContentHint: true by default.

WebMCP is a communication surface, not the authority boundary. Approval verification, commit authority, state binding and provider credentials remain on the server.

MCP 2026-07-28

The same transaction tools for external agent hosts.

PACT registers the same inspect, preview, approve, commit, verify, receipt, rollback and cancel catalog into an application-owned MCP server. Use the official current MCP SDK for Streamable HTTP or stdio; PACT does not hand-roll the transport.

The MCP protocol core can be stateless while the PACT transaction remains durable application state. Protocol transport and transaction authority are deliberately separate.

CAPABILITY LIFECYCLE

Agents get transactions, not ambient write access.

Intent → exact preview → verified human authority → state-bound commit → canonical verification → receipt.

The same lifecycle applies whether the caller is browser WebMCP, an MCP agent host, a CLI or an ordinary API client.

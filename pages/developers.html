WEBMCP

WebMCP developer surface

PACT dynamically exposes only capabilities that are valid for the transaction's current state. Commit does not exist as an agent capability before human approval.

capability lifecycle
IDLE      → pact_autopilot_prepare
PREVIEWED → pact_request_human_approval
APPROVED  → pact_autopilot_finish
COMMITTED → pact_autopilot_resume_verify
VERIFIED  → pact_get_transaction_receipt
          → pact_rollback_transaction

Expert mode also exposes granular lifecycle tools.
DYNAMIC AUTHORITY

The tool surface changes with state.

PACT uses the browser's WebMCP model context to register the capabilities currently valid for the transaction. Registrations are lifecycle-bound to an AbortController generation so stale capability definitions are removed.

The default agent path uses aggregate tools: prepare everything safely, pause once for trusted human approval, then finish commit + verification automatically. If a crash or persistence interruption leaves a durable COMMITTED state, pact_autopilot_resume_verify resumes verification without re-approval or duplicate commit. Granular lifecycle tools remain available in the expert workspace for inspection and fault testing. Every mutating tool re-enters the same engine used by the human UI and uses the same durable persistence boundary.

WHY THIS MATTERS

Agent permissions become inspectable protocol state.

Instead of exposing one broad “admin” action, PACT's discoverable WebMCP tools mirror the transaction lifecycle.

A judge can inspect exactly when authority appears, when it disappears, and what evidence is produced afterward.
